## Цель

Ответить на исследовательский вопрос (§44): при каких размерах объектов, количестве операций и размере batch GPU даёт выигрыш над CPU с учётом передачи данных, аллокаций, синхронизации и запуска kernel'ов. GPU-код собирается и запускается автором на GPU-машине (`docs/gpu_workflow.md`), поэтому здесь заранее готовятся сценарий запуска и анализ: присланный архив должен сразу превращаться в таблицы и графики.

### Часть А: что сделано

* **`bench/analysis/analyze.py`** (pandas + matplotlib; запуск: `analyze.py run1.csv [run2.csv ...] --out DIR`). Читает CSV от `vault benchmark`
  (в том числе старые, без `entropy_ms`), отделяет измеренные строки от `skipped`, берёт медиану по прогонам. Выход:
  `speedup.csv` (CPU_total / кандидат_total против `cpu` **и** против `cpu-mt`; отдельно `cpu-mt` против `cpu`),
  `crossover.csv` (по каждой оси: число объектов при фиксированном размере и размер при фиксированном числе для SHA3/Merkle build;
  число листьев для Merkle verify; batch для шести PQC-операций), `transfer_bw.csv` (эффективная ширина H2D по разбивке фаз),
  `summary.md`, `plots/*.png`. Результат пересечения явный: `always` / `never` («нет пересечения в диапазоне») / `crossover` /
  `crossover_down` (GPU выигрывает только на малых размерах) / `mixed` / `insufficient`; точка — интерполяция линейная по
  log(speedup) от log(x), для степенной кривой s = x/x₀ она восстанавливает x₀ точно (тест).
* **Графики:** throughput от размера (панели по числу объектов), ops/s от batch, stacked bar фаз GPU (alloc/H2D/kernel/D2H/sync/entropy +
  «other» = total − сумма фаз; при double buffering фазы перекрываются), heatmap speedup (размер × число объектов) для SHA3 и Merkle
  build по каждой паре GPU/baseline (диверджентная шкала blue↔red с нейтральной серединой в 1×, подписи в ячейках). Палитра — проверенная
  валидатором категориальная (`validate_palette.js`, light): цвет закреплён за backend'ом (`cpu` — синий, `cpu-mt` — оранжевый,
  `gpu` — зелёный, прочие GPU-конфигурации — следующие слоты, более 8 серий — нейтральный серый), у части слотов контраст ниже 3:1, поэтому
  линии различаются ещё формой маркера, подписаны на конце и есть легенда; таблицы с теми же числами — в `summary.md`.
* **`summary.md`:** окружение (из `results.json`), покрытие и причины пропусков, таблицы пересечений, максимум/минимум speedup, эффективная
  ширина H2D, стабильность медиан между прогонами (разброс = (max − min) / медиана; доля точек > 10 %; худшие точки), список графиков.
  Файл детерминирован (нет времени/случайности), числа не правятся вручную.
* **Тесты** (`bench/analysis/test_analyze.py`, `test_run_all.py`; 38 штук, `python3 -m pytest bench/analysis` или `ctest -L analysis`):
  реальный CPU-прогон (`fixtures/cpu_quick.csv/json`, получен `vault benchmark --config bench/configs/quick.json`); **синтетические GPU-данные**
  (`fixtures/gen_synthetic.py`, committed `synthetic_gpu.csv`): GPU быстрее везде, медленнее везде, пересечение внутри диапазона
  (аналитически известная точка), выше и ниже диапазона, немонотонная кривая, `skipped` по `max_total_bytes`, упавший backend (все точки
  skipped), backend отказывается от части операций (ML-DSA без ctx), несколько GPU-конфигураций, старый CSV, только skipped-строки, два
  прогона с известным разбросом, детерминизм, ошибки входа. Анализ не падает ни на одном варианте.
  Учёт записей с ошибкой самопроверки: самопроверка benchmark'а (ревью этапа 4) при расхождении **прерывает** прогон исключением, CSV не
  пишется, а `gpu_run_all.sh` фиксирует шаг как `fail` с логом — «быстрых неверных» строк в данных не бывает.
* **`scripts/gpu_run_all.sh`** (+ расширенный `check_gpu_env.sh`): шаги, каскад сборки (CUDA + cuPQC → CUDA без cuPQC → CPU), статусы
  `ok/fail/skipped` в `RUN_SUMMARY.txt`, лог на шаг, `nvidia-smi` clocks/temperature/power до и после полного прогона, `ptxas_kernels.txt`,
  `cupqc_report.txt`, архив через `trap EXIT`; подробности — `docs/gpu_workflow.md`. Прогнан здесь в CPU-режиме до конца (`--quick`):
  сборка/ctest — по хукам, smoke (в т.ч. порча подписи → код 2) и `quick.json` — реально, GPU-шаги `skipped`, архив с анализом собран.
  Сбой шага не останавливает остальные (проверено подменой `vault` на падающий скрипт).
* **Стенд:** Release = `-O3 -DNDEBUG` без `-march=native`; CMake предупреждает о `-march=native`, а скрипт помечает `fail`; флаги, версии и
  коммит с `-dirty` — в `results.json` и в `summary.md`; в `SystemInfo` попадают флаги nvcc и архитектура (`VAULT_CUDA_FLAGS`).
* **`docs/report/README.md`** — каркас отчёта без выводов: как получены данные, что в `summary.md`, пустая таблица «CPU/GPU предпочтителен»,
  чек-лист объяснения границ (launch overhead, PCIe, аллокации, последовательность sponge, divergence ML-DSA, VRAM, entropy), рекомендация
  для vault, ограничения эксперимента.
