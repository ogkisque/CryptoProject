# Этап 7: комплексное экспериментальное исследование

**Статус:** ☐ не начат  ·  **Где:** **GPU-машина** (сбор данных) + любая (анализ)  ·  **ТЗ:** план → Этап 7, `crypto_project.md` §44–§49, §56

## Цель

Ответить на исследовательский вопрос (§44): при каких размерах объектов, количестве операций и размере batch GPU даёт выигрыш над CPU с учётом передачи данных, аллокаций, синхронизации и запуска kernel'ов.

## План работ

### 7.1 Подготовка стенда
- [ ] Release-сборка с фиксированными флагами (`-O3 -march=native`? — решить и записать; для воспроизводимости лучше без `-march=native` или с явным указанием).
- [ ] CPU governor `performance`, отсутствие фоновой нагрузки, GPU в P0 (`nvidia-smi -q -d PERFORMANCE`). Зафиксировать температуру и частоты до и после прогона.
- [ ] `SystemInfo` полностью заполнен (§49): CPU, GPU, arch, CUDA, cuPQC, компилятор, флаги, git commit.

### 7.2 Сбор данных
- [ ] `./scripts/run_bench.sh bench/configs/full.json`. Warm-up ≥ 3, measured ≥ 10 (для малых задач — больше, например 100, чтобы снизить шум).
- [ ] Отдельные прогоны для анализа влияния факторов:
  - pinned и pageable память;
  - total с `cudaMalloc` и с пулом буферов (§48 «memory allocation»);
  - один stream и double buffering (SHA3);
  - cpu (1 поток) и cpu-mt (все ядра).
- [ ] Повторить полный прогон 2–3 раза в разное время и проверить стабильность медиан.

### 7.3 Анализ (`analyze.py`)
- [ ] mean / median / min / max / stddev по каждой точке (частично посчитано уже в C++, но пересчитывается из сырых данных, если они сохранены).
- [ ] speedup = CPU_total / GPU_total (медианы) против cpu и против cpu-mt.
- [ ] crossover point для каждого класса операций: SHA3 (по количеству при фиксированном размере и по размеру при фиксированном количестве), Merkle build, Merkle verify, по каждой из шести PQC-операций (по batch). Интерполяция в log-шкале.
- [ ] Графики: throughput (GB/s) от размера объекта для нескольких количеств; ops/s от batch; stacked bar разбивки GPU-времени (alloc / H2D / kernel / D2H / sync) — показать, какая доля уходит на накладные расходы; heatmap speedup (size × count) для SHA3.

### 7.4 Выводы
- [ ] Таблица «CPU предпочтителен / GPU предпочтителен» по классам операций и диапазонам.
- [ ] Объяснение каждой границы: launch overhead, PCIe-трансфер (оценить по `bandwidthTest`/H2D GB/s), последовательность sponge, divergence в ML-DSA sign, объём VRAM.
- [ ] Практическая рекомендация для архитектуры vault: какой backend выбирать в `verify` при каком размере хранилища. Возможна эвристика auto-backend (опционально).
- [ ] Ограничения эксперимента: одна модель GPU, модель доверенной области, отсутствие power-loss тестов.
